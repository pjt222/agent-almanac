### R2-N2 [should-fix → should-fix] files/scripts/build-hermes-distribution.js @ main() line 676, `if (against && !(existsSync(against) && lstatSync(against).isDirectory()))`

**Claim:** The new `--against` guard uses `lstatSync`, so a checkout reached through a symlinked path is refused with exit 2 even though `diffTrees` walks it without difficulty. The guard is stricter than the consumer it protects — the shape this repository's CLAUDE.md names as 'guard by the accept-list, not a proxy'.

**Evidence:** `existsSync` at 676 follows symlinks and returns true for `link -> /path/to/checkout`; `lstatSync(link).isDirectory()` is false for the link itself, so the conjunction fails and main prints '--against <path> is not a directory' and returns 2. What the guard is protecting is `diffTrees` → `index(againstDir)` → `walk(againstDir)` → `readdirSync(abs)` (393), which follows a root symlink and enumerates the target fine; only entries BELOW the root are lstat'd, deliberately (walk's docstring, 387-388). So the accept-rule is 'readdirSync can enumerate it', for which `statSync(...).isDirectory()` is the matching predicate and `lstatSync` is a proxy that rejects a valid input. Round-1 G2's refuter named exactly this ('should use `statSync(against).isDirectory()`, not `lstatSync` — lstat would reject a checkout reached through a symlink that diffTrees walks fine'); the finding's own fix text said lstatSync, so I am filing it as new rather than as G2 unapplied. inferred — decide with: `ln -s "$PWD/dist" /tmp/distlink && node scripts/build-hermes-distribution.js --check --against /tmp/distlink; echo $?` (expect 2 today, 0 or 1 after the fix).

**Fix:** Use `statSync(against).isDirectory()` (importing `statSync`), which is consistent with the symlink-following `existsSync` beside it and with what `walk` accepts. Test 471's `['--check','--against', join(root,'SOUL.md')]` case passes under either spelling, so the change is test-neutral; add a positive case pointing `--against` at a symlink to a good build and assert status 0.

**Refuter:** VERIFIED — the finding holds on my own reading; severity should-fix is correct.

STEELMAN FIRST. The generator is deliberately symlink-hostile (header 45-48; `walk` never follows; `copyTree` refuses; `diffTrees` calls a symlink in the checkout drift at 607), and `prepareOutDir` uses the same `lstatSync(...).isDirectory()` spelling at 476. On that reading, refusing a symlinked `--against` root looks like one uniform policy rather than a defect, and the refusal is loud and fail-safe.

MECHANISM CONFIRMED. build-hermes-distribution.js:676 is `if (against && !(existsSync(against) && lstatSync(against).isDirectory()))`. `existsSync` follows symlinks and is true for `link -> /path/to/checkout`; `lstatSync(link).isDirectory()` is false (the lstat mode is S_IFLNK), so the conjunction fails, main prints `--against <path> is not a directory` and returns 2. The consumer that guard protects is `diffTrees` (597) -> `index(againstDir)` -> `walk(dir)` -> `visit(dir, [])` -> `readdirSync(dir)` at 393, and readdir resolves a symlinked final component, so the target is enumerated normally. Only children are lstat'd (396), and the root is never pushed into `out`, so the accept-rule really is "readdirSync can enumerate it" — for which `statSync(...).isDirectory()` is the matching predicate. The proposed fix also introduces no spurious `drift: symlink in the checkout` for the root, since walk never lstats its own argument.

BOTH REFUTATION PATHS FAIL. (a) "lstat is a deliberate policy": round1-to-round2.diff:639-640 shows the guard was applied verbatim from round-1 G2's Fix text with no justifying comment, and the header's `--check --against <dir>` documentation (84-90) describes it as "a checkout of the distribution repository" with no symlink clause. The policy reading is speculative, not recorded. (b) "prepareOutDir at 476 uses lstat identically": not analogous — prepareOutDir rm -rf's through that path (483-485), so refusing to delete through a link is prudent; `--against` is read-only, so the same spelling there has no corresponding reason.

SEVERITY. should-fix, not blocking: exit 2 is the honest "could not measure" code, `--against` is wired into no workflow (publish-hermes-profile.yml uses `--check` at :114 and `--out "$RUNNER_TEMP/dist"` at :152; generated-artifacts.yml now states "`--check --against <dir>` ... is not wired into any workflow"), and pr-body.md:58's `--check --against` evidence row used a real directory, so no evidence claim is contradicted. Not a note either: a guard that rejects an input its own consumer accepts is the class CLAUDE.md names explicitly ("guard by the accept-list, not a proxy like existsSync"), the emitted diagnostic is factually false for the rejected input, and the fix is one identifier plus one positive test. Test 471's `['--check','--against', join(root,'SOUL.md')]` case is a regular file and exits 2 under either spelling — verified test-neutral as the finding claims.
