## [Unreleased]

### Added
- **`tools/review-findings.mjs`** and **`tools/agent-report.mjs`** — the two scratchpad scripts the 2026-09-02 review rounds ran by hand, promoted under the standing rule that scratchpad findings become tools. The first turns a lens → refuter review workflow's task output into the findings file the next round reads (with a data-not-instructions line under its title) plus a verdict table, and refuses — exit 2, never an empty render — an input with no `lenses` or an empty list, extra arguments, or a failed write; the second recovers a subagent's final report from its transcript by a marker in its title, byte for byte, for the case where the notification truncated it and the subagent's own Write was blocked, and refuses a transcript whose parsed lines carry no assistant role rather than reporting "marker not found". Both carry `--verify` with fixtures that exercise every guard and the CLI exits; the first also renders a committed excerpt of a real round-2 result (`tools/fixtures/`) against its expected file. The workflow seed that should feed the first directly is #778. Also removes the check and plant counts from `tools/README.md`'s harness row, which had gone stale twice — the tool prints them — after its own adversarial review (9 should-fix, all applied; the review was itself recovered with `agent-report.mjs`).
- **Hermes profile distribution** (companion #78): `scripts/build-hermes-distribution.js` emits the almanac as a Hermes *profile distribution* — a separate, generated repository (`pjt222/agent-almanac-hermes-profile`) holding `distribution.yaml`, a byte copy of the root `SOUL.md`, a generated README, the LICENSE and `skills/<id>/` for exactly the registry's ids, installable with `hermes profile install github.com/pjt222/agent-almanac-hermes-profile`. Nothing else at the root, because Hermes copies every top-level entry of the cloned tree into the consumer's profile. Build-gates run on the emitted tree and are all blocking: any path component at any depth in Hermes's 37-name `USER_OWNED_EXCLUDE` (the v0.13.0 pin filters it silently on install; upstream main filters only at the root) or its `EXCLUDED_SKILL_DIRS`; `_`- and `.`-prefixed directories; symlinks anywhere, the root inputs included (the pin dereferences them, upstream main refuses the tree); exactly one `SKILL.md` per skill at its root so the pin's `rglob` count and upstream's excluded-path count agree; count == registry `total_skills` == entry count == the whole number in the manifest description, and a check that scanned no files is itself red; the four secret literals and the `$0.55/day` constant in every emitted file, the manifest and README included; the manifest re-parsed from disk, every field (Hermes name rule, `version`, `author` and `license` mirroring `package.json`, no `env_requires`, no `distribution_owned`). Build goes to a temp directory first and is gated there, so `--out` writes nothing on a red build; it refuses (exit 2) an `--out` inside the source tree, a root-level entry it did not write, an empty registry, a registry id that is not its directory name, and any crash (never exit 1). `--check` is a required CI step in `validate-skills.yml`; `--check --against <checkout>` is the regenerate-and-diff, with no content exclusions because the output carries no timestamps or shas, executable bit included — mode bits beyond the executable bit and empty directories are outside it. `.github/workflows/publish-hermes-profile.yml` builds from each `v*.*.*` tag and pushes through a deploy key: red on a release tag until the operator adds the secret (a green tag that published nothing is the failure #78 exists to prevent), dry-run by default on dispatch, tag-gated on every event, serialised, pinned to GitHub's published host key, and refusing to publish a version lower than the one already there; declared an external publisher in `check-workflow-generator-inputs.js`, which holds that declaration to a read-only token. `tools/validate-hermes-distribution.py` installs a distribution with Hermes's *own* `profile_distribution.py` (pointed at by `--module`, never committed here) into a temp profile root — asserted by path and containment, not assumed — and runs sixteen checks against the companion's done-criteria, including the module's user-owned set and the stub's excluded-directory set against the generator's own exports (read through node when `--almanac` is given); `--verify` plants fourteen defects and requires each to redden one of its own named checks. Measured against the v0.13.0 pin the VPS ran until 2026-09-02 and against upstream main (2026-09-02): 16 of 16 checks green on the real build, 14 of 14 plants red on both. The 2026-08-19 thread's warn-only-plus-ratchet decision for the count assertion is deliberately not taken: it was made for an in-place layout, and with the payload built from registry ids the count is exact by construction.
- **`workflows/verify-handoff.mjs`** — adversarially verifies a `CONTINUE_HERE.md` draft against a facts file (each fact naming the command that produced it) and its sources: traceability, completeness against the previous edition and/or plan, actionability — up to three read-only lenses per draft in parallel. Promoted from the 2026-09-02 session scratchpad; this entry is the canonical list of what the two ad-hoc runs it was distilled from caught: a heartbeat claim extrapolated over five unread days (a `tail -6` quoted as "every day since the 20th"), a "six phases" count for a seven-phase plan, a test that pinned the absence of the last bad value rather than the value, and a Context section claimed verbatim whose Links block had been rewritten. Nothing is dropped silently or reported clean by accident — malformed drafts, non-string sources, dead lenses, lenses that returned unusable output, a draft with no sources (completeness skipped) and missing results are all logged and all reach the return value's `coverage` block, next to an aggregate `blocking` count, so a caller gates on "0 blocking and coverage complete" rather than on the log; `dryRun: true` exercises every normalisation path without spawning an agent; file contents are declared data, not instructions. `write-continue-here` 1.0 → 1.1 gains the producing steps (a facts file in Step 1, a draft in Step 2, verify-then-install in Step 3 with the findings file the next round needs), a `Verified:` header field, two Validation items and three pitfalls.
- **`tools/review-bundle.sh`** — builds the self-contained bundle an adversarial reviewer needs when it must not read the working tree: diff against a base ref, full copies from HEAD of every added, modified, renamed or type-changed source file, the PR body, and a README that says to read nothing else. One matcher — git's own pathspec — decides what `--summarise` reports as stat plus sample, for the diff and the copies alike; paths are read with `core.quotePath` off; it runs from any subdirectory; it refuses (exit 2) rather than shipping a silent zero-byte copy, an unreadable body, or a bundle on top of an old one. `--verify` builds a throwaway repo with a rename, a deletion, a file-to-symlink type change, a non-ASCII path with a space, a working tree that differs from HEAD and two summarised files under a bare-directory pathspec; runs from a subdirectory with a relative `--out`; and asserts the copy set equals the expanded changed set minus deletions, `--sample` bounds the hunks at two distinct values, and six refusals exit 2.
- **`tools/merge-dependabot.sh`** — merges open Dependabot PRs oldest-first, re-polling mergeability before each merge because the shared lockfile flips the rest to UNKNOWN and then CONFLICTING; reads the verdict from the API (`state` and a merge commit), never from gh's stderr; asks Dependabot to rebase on a conflict. BLOCKED is polled, not skipped: GitHub reports BLOCKED for required checks that are merely pending, and every merge re-triggers the next PR's checks, so a tool that skipped it would merge one PR per run (caught in review before merge). The decision table is a function; `--verify` pins one case per pattern alternative and the arm order with mixed pairs, then drives the real `run` through a fake `gh` (`GH=`) that logs every call, so the assertions read what was invoked — merge exactly once, BLOCKED polled exactly the poll budget, an unreadable PR polled exactly twice — across the merge, conflict, blocked, unreadable, refused-merge, draft, null-field, unreadable-verdict and dry-run paths. Offline, no gh needed. Lists up to 200 PRs, and a failing list exits 2 instead of reading as "no PRs".
- **Adapters declare which install scopes they can honour** (`static scopes`), and the installer warns once per adapter when `--scope` will not be honoured — on install, uninstall, audit, and dry runs. #607 reported this for `hermes`; measuring it found **nine** adapters of thirteen accept the flag and ignore it, in both directions: `hermes` and `openclaw` are always global, while `ai-edge`, `aider`, `codex`, `copilot`, `cursor`, `gemini` and `windsurf` are always project — so `--scope global -f cursor` was silently downgraded exactly as `--scope project -f hermes` was, and the issue named only the first. The warning reports; it does not redirect. Which scope an adapter uses is unchanged — the defect was never that hermes installs globally, it was that nothing said so, while the dry run printed the wrong scope's path as though the request had been honoured (#607).

### Fixed
- **`mutation-check` could not reach `INVALID` for any non-JavaScript file, and said it had checked** (#758). `parses()` returned `true` for every extension outside `.js`/`.mjs`/`.cjs` while step `[3/5]` printed `it parses`, so a `.py` mutant with its `def` colon removed — a file Python cannot import — scored `MUTANT KILLED by 1 failing test(s)`: the count was a test asserting the generator exits 0, red because the file was broken, byte for byte indistinguishable from a real kill. The gate is now `scripts/lib/mutation-parse.js`, a verdict rather than a boolean: one checker per type (`node --check` through the module-typed probe as before; `python3 -I compile()`, `bash -n` and `Rscript --vanilla parse()` on stdin; `js-yaml` and `JSON.parse` in-process), named on the pass path (`it parses (python3 compile())`); a type with no checker is refused **before** a baseline is spent, because the `INVALID` verdict would be unreachable for it; an absent interpreter, a checker killed by a signal, or a parser that threw rather than answered is `INCONCLUSIVE`, never a pass and never `invalid`; an original that already fails its checker is refused too, with no override; and `.md`/`.markdown`/`.txt` proceed with `no syntax to check (.md)` so a documentation-gate proof still runs. `workflows/*.mjs` are checked in the Workflow dialect (wrapped as the runtime wraps them, the recipe `_template.mjs` documents), because plain `node --check` rejects their top-level `return` unmutated — the first #773 proof reported `INVALID MUTANT` on an original for that reason. The adversarial review of the first draft supplied the sharp edges: `ast.parse` accepts `return 1` at module level and `compile()` does not, so the python checker is `compile()`; `-I` and `--vanilla` keep a broken `sitecustomize` or `viz/.Rprofile` from making a good file "not parse"; `status: null` from a signalled checker was being scored `invalid`. Measured on the issue's own command against the shipped code: `INVALID MUTANT — the mutated file does not parse (python3 compile())`, quoting the interpreter's own traceback, where it read `MUTANT KILLED by 1 failing test(s)`. 26 tests, 7 of them end to end through the tool in throwaway repositories — one on a PATH holding only `node` and `git`, one whose test command genuinely goes red on the broken mutant so the old behaviour would have printed `MUTANT KILLED` — plus every `workflows/*.mjs` parsed under the dialect, with the raw-ESM negative arm gated on the files that actually carry a top-level `return`. Not closed here and said so: `crashSuspicion` still matches node runtime-error text only, so a non-JS mutant that parses and then fails at import reads as a kill.
- `resolveHermesHome()` returned `$HERMES_HOME` raw while its other two tiers returned `resolve()`d absolute paths. The *documented* type was only `{string}`, which all three satisfied — absoluteness is a contract this change introduces, not one it restores — but one function returning two different shapes depending on which tier answered is a defect regardless. All three now normalize before returning. This fixes the **inconsistent shape, not the relativity**: a relative `HERMES_HOME` is still resolved against the working directory, now once at the source instead of once at each of the four call sites, so invocations from different directories generally still see different homes. A whitespace-only value is now treated as unset, on the argument that `" "` is a quoting accident rather than a directory name; the value that is *used* is never trimmed, so a POSIX-legal path with a leading or trailing space survives byte-for-byte. The pre-existing `$HERMES_HOME` test built its fixture with `resolve()`, on whose own output `resolve()` is idempotent, so it passed identically with the bug present. Four tests are added, of which **two** discriminate the fix from the bug — the relative and whitespace-only cases; the empty-string case was already green on the old body and is a pin rather than evidence (#611).

**`cli/` is byte-identical to `1.9.0`.** This is a content release, not a code one — every breaking change described under `[1.9.0]` still applies and still describes the CLI you get. Read that section before upgrading from `1.3.0`.

## [1.9.0] - 2026-08-19

The last release of the JavaScript CLI. The version number is deliberate: `2.0.0` is held for the Rust port (#256), so this line ends at `1.9.x`.

**Read the Breaking section before upgrading.** The number says minor; three of the changes below are breaking in fact. Nothing has been released since `1.3.0` (2026-05-04), and the changes accumulated in that window include a Node floor raise. A minor version is a weaker warning than these changes deserve, and this notice is the compensation for it.

### Breaking
- **Node.js 22.12.0 or newer is now required** (`engines.node` was `>=18.0.0`). The floor was raised on 2026-06-04 when the CLI moved to commander 15 — a month after `1.3.0` shipped — so this is the first published release that carries it. Node 18 and Node 20 users must upgrade Node; `npm install` will warn rather than fail, so an unattended install can leave a CLI that cannot start.
- **`almanac audit` now exits non-zero when it finds problems** (#439). It previously exited `0` unconditionally, so any script, CI step, or pre-commit hook that ran `audit` was passing regardless of what the audit said. Those callers will now start failing — which is the point, but it will look like a new breakage rather than a newly visible old one. Adapter crashes are also marked structurally rather than being reported as ordinary findings.
- **`--version` now reports the real version** (#456). `cli/index.js` hardcoded `.version('0.1.0')`, so the *published* `1.3.0` binary answers `--version` with `0.1.0`, and has answered wrongly for every release since `0.1.0`. Anything that parses `--version` will see it jump from `0.1.0` to `1.9.0`. That jump is this bug being fixed, not a version skip; the value now derives from the package manifest and cannot drift again.

### Fixed
- `cli/index.js` — `--version` no longer hardcoded; derived from the manifest (#456). See Breaking.
- `cli/lib/` chalk factory — the colour fallback was broken, silently degrading output rather than falling back cleanly (#455, #457).
- `opencode` adapter audit — the `ok` line counted entries that were not valid, so a passing audit could overstate what it had checked (#445).
- `claude-code` adapter audit — `base` is now declared; it was referenced undeclared (#365, #373).
- js-yaml 5 compatibility — namespace imports, after the ESM default export was removed upstream.
- `scripts/lib/english-history.js` + `scripts/lib/translation-status.js` — the comment table documenting the shared English-history walk was falsified by #597 and never updated. Tag-sequence parity (#481) added a **sixth** collector over that walk, `history.sequences` (`scripts/lib/fences.js`), which the table did not list; `rg -n 'sequence' scripts/lib/english-history.js` returned nothing. The stale clauses were not a matter of changing "five" to "six": the new member goes **both** ways under a shrunk pool, so the three-way tally ("two tighten, two loosen, one is untouched") could not survive it. Losing the revision whose sequence matched turns a legitimate translation into a retag finding (strict); losing the last revision with the same fence count demotes a real retag to `unalignable`, which is expressly not a finding (lenient). The table now says which five sort and why the sixth does not. Also corrected: the walk has **three production** callers, not two — `scripts/measure-tag-sequence-parity.js` is named as a consumer rather than scoped out, because `fences.js` cites it as the reproducer for the tag-sequence finding set. The qualifier is load-bearing: `rg walkEnglishHistory` returns a fourth call site in `scripts/test/`, and an unqualified "three" would be a count refuted by the obvious grep — #599's own defect, reintroduced by its fix. Nothing asserts these counts mechanically; there is no gate here and no mutation was run. (#599)
- `cli/adapters/hermes.js` + `cli/lib/detector.js`: the Hermes home is now resolved via `cli/lib/hermes-home.js` — `$HERMES_HOME` first (authoritative on every platform), then the Windows-native default `%LOCALAPPDATA%\hermes` (accepted only when its `config.yaml` exists), then `~/.hermes` (the Unix default, and the legitimate home for Hermes inside WSL). Previously `detect()` and both install bases hardcoded `homedir()/.hermes`, so a Windows-native Hermes install was invisible to `detect` and installs, and only a manual directory junction made anything fire (#604). The two HOME-redirected test blocks now also pin `HERMES_HOME` and clear `LOCALAPPDATA`, which fixes the hermes broken-symlink audit case leaking to the real user profile on Windows — `os.homedir()` ignores `$HOME` on win32, so the old steering never reached it.
- i18n stub detection: a stray fence opener that *pairs* with a real fence inverted the document's fence phase and hid prose from comparison. An added ```` ```bash ```` cannot close anything (a closer carries no trailing text) but it opens, so the real opener was swallowed into its body and the real closer closed the stray fence. Measured: `total` 5 → 3, verdict `no-novel-lines` (a scaffold) → `insufficient`, which is counted as **translated**. One added line laundered a scaffold. #558 fixed only the *unterminated* case and passes this fixture. Detected now by comparing the file's fence **shape** — the ordered list of info-string tags, which are keep-in-English in every locale — against every shape its English source has ever had. Shape, not count: the flip leaves the count unchanged. Tags, not bodies: #477's backlog leaves 1,220+ bodies diverging, so a body comparison would refuse to judge much of the corpus. Terminated fences only, so #558's unterminated case keeps its `stub` verdict — and so the check needs no second "did the mask hide lines?" condition, which an earlier draft carried and which left a worse hole open: a stray ```` ```text ```` opener is localisable, hides nothing, and instead **exposes** the real frozen body, whose keep-in-English lines then read as novel prose and reported `has-novel-lines` — a positive claim of translation. (#561)
- `scripts/generate-readmes.js` — the published README translations table counted files, not translations, so every cell was `translated + stubs`: it read `de 383/500 (76.6%)` where `i18n/de/translation_status.yml` measured `347/500 (69.4%)`. The table now renders the status files' figures verbatim (denominators and `pct` included, so the two surfaces cannot disagree by rounding) and breaks `stubs` out as its own column. Existence counting survives only for a locale with no status file, and such a cell is marked `*`. (#560)

### Added
- Broken symlinks are now reported in six adapter audits (#438). A dangling link previously read as a healthy install.
- `unjudged` count in every `translation_status.yml`, and an `UNJUDGED` line in `translation:status --verdicts`. A file whose fence mask cannot be trusted is counted as neither translated nor stub: counting it translated inflates coverage, and calling it a stub routes a possibly fully-translated file into a remedy that deletes it. (#561)
- `scripts/check-readme-translation-parity.js` + integrity check B13 — gates the README table against `i18n/*/translation_status.yml`. It parses both committed artifacts and never calls the generator: a regenerate-and-compare gate agrees with any generator bug, which is why `check-readmes` passed throughout (it also runs only in `release.yml`). Iterates locales rather than table rows, so a deleted row is visible. (#560)

### Changed
- Content shipped in the package, counted from the registries at the `v1.3.0` tag rather than from a directory listing: **skills 350 → 370**, **agents 72 → 75**, **teams 17 → 22**, **guides 26 → 35**. (The tag is the right baseline, not the release-prep commit before it — a 26th guide landed in the merge that got tagged, and `release.yml` publishes the tag's tree.)
- Packaging: the authoring templates — `skills/_template/`, `agents/_template.md`, `teams/_template.md`, `guides/_template.md` — are no longer published (#669). They are scaffolding for authoring new content, not content, and shipping them meant a consumer globbing the installed directories counted one more of each kind than the registries declare (371 skills against a registry, README and `check-readmes` that all say 370). With them excluded, every shipped count now equals its registry exactly: 370 skills, 75 agents, 22 teams, 35 guides. Nothing under `cli/` references any of them, so the exclusion is invisible to the CLI itself.
- CI: `update-readmes.yml` now runs `translation:status` **before** `generate-readmes.js`. With the table deriving from the status files, the old order rendered last cycle's numbers while the same commit overwrote the file it read. The job also asserts parity before auto-committing, and `scripts/lib/translation-status.js` was added to its trigger paths — the #553 lib extraction meant a change to what counts as an untranslated scaffold did not regenerate the counts it decides. (#560)
